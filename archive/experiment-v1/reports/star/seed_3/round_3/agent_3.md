This isn't "coordinate transformation" or "change-of-basis formulas"—it's **bijective correspondence between distinct combinatorial structures**. Puzzles encode **boundary conditions** for partial flag varieties. LR-tableaux encode **filling procedures** for skew Young diagrams. These aren't "shadows of the same algebraic object"—they're genuinely different combinatorial data that happen to count the same thing. The bijection problem asks whether there exists a **structure-preserving correspondence** that explains why they count identically.

Migration succeeds precisely because it respects the **local constraints** that define each structure. ## WHERE GROWTH DIAGRAMS ACTUALLY FAIL

The synthesis completely misses why direct growth diagram approaches struggle. It's not about "coordinate transformations"—it's about **information density**. 

In row-by-row transfer matrices, each step must encode:
1. Current puzzle configuration (exponential in row position)
2. Partial tableau state (depends on previous rows)  
3. Consistency conditions (global constraints)

Face labels in growth diagrams work when local information suffices to determine transitions. But LR-tableaux have **global rectification properties** that resist local encoding. The reading word must satisfy intricate descent conditions that depend on the entire tableau shape.

**Key insight the synthesis misses**: Migration works because mosaics provide a **global coordinate system** where local moves respect global constraints. Row transfer approaches fail because they try to maintain global consistency through local rules alone.
